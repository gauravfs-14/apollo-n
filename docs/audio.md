# Audio

All sound runs through Howler's single AudioContext (`web/game/core/audio.ts`). Master volume is `Howler.volume`, saved as `apollo.volume`; music volume is saved as `apollo.musicVolume`.

## Sound effects

`sfx(name, { volume, rate })` plays `/audio/sfx/<name>.mp3`, cached after first use. Missing files fail silently. Current effects: `beep`, `boom`, `buzz`, `chime`, `clank`, `click`, `hiss`, `ignition`, `rocket_roar`, `rumble`, `staging`, `thunk`, `whoosh`.

## Music

One looping track at a time, crossfaded over 1.5 s. If the browser blocks autoplay, music starts on the next click or key press. Tracks are `/audio/music/<id>.mp3`, all by Kevin MacLeod (CC BY 4.0, credited in Settings).

| Track | Phases |
|---|---|
| `menu` | select |
| `prep` | build, crew |
| `prelaunch` | board, checklist |
| `launch`, `cruise`, `site`, `landing`, `surface`, `report` | The phase of the same name |
| `hurdle` | Played over cruise during a hurdle (`setMusicOverride`) |

## Ambience

Looping beds under the music (`web/game/core/MissionAudio.tsx`): mission control room (`mcc`) for board, checklist and report; cabin for cruise, site and landing; spacesuit for the surface.

## Voices

`speak(text, lineId?, { speaker, label })` plays one radio line.

1. On first use the client reads `GET /health`. If the server's voice provider is `elevenlabs`, lines are fetched as clips from `POST /voice`.
2. Clips are decoded, trimmed of leading and trailing silence and played through the radio chain.
3. If there is no clip (voices off, network error, timeout after 12 s), the browser's `speechSynthesis` reads the line instead.

When a mission starts, every line it can play is sent to `POST /voice/prefetch` so clips are ready before they are needed. The list is built by `allLines(plan)` in `web/game/core/voiceLines.ts`.

Speakers and their ElevenLabs voices are set by environment variables (see [Getting started](getting-started.md#configuration)):

| Speaker | Who | Caption |
|---|---|---|
| `capcom` | Mission control | Houston · CAPCOM |
| `crew` | Commander | Commander |
| `crew2` | Lunar module pilot, recovery | Lunar Module Pilot |
| `pao` | Public affairs | Apollo Control |

## Radio chain

Every transmission is processed to sound like an Apollo-era voice loop: band-limiting filters, soft saturation, a slight level waver, band-passed hiss through a shared compressor, a key-up noise burst, crackle and a squelch tail. CAPCOM transmissions are bracketed by Quindar tones (2525 Hz before, 2475 Hz after, 0.25 s each). Each speaker has its own profile.

## Comms script

`web/game/core/comms.ts` queues radio lines with `say(lines, { interrupt, once, onDone })`. Lines can carry a `maxDelay` after which they are dropped if they haven't played, so callouts never arrive late. A short gap separates different speakers.

The script itself is in `web/game/data/missionComms.ts`: builder functions for each event (`launchCues`, `hurdleResult`, `probeReport`, `simReport`, `altitudeCall`, `landed`, `taskDone` and so on). Each returns `CommLine`s. Wording is picked by a hash of the mission seed and the event, so it varies between missions but stays stable within one. The tone follows difficulty: warm on easy, crisp on normal, clipped on hard. Templates `{N}`, `{LM}` and `{BASE}` fill in the mission number, lander call sign and base name.

The wording is adapted from public-domain Apollo 11 transcripts. Voice clips generated by ElevenLabs are cached in `api/data/media/voice/`.
